# 第一次使用 Shellter

[English](GETTING-STARTED.md) · [简体中文](GETTING-STARTED.zh-CN.md) · [README](../README.zh-CN.md)

建议先用示例。示例在临时 HOME 中创建配置，不会碰你真实的 Codex、Claude 等客户端配置。不需要 API key、原生 agent 或 MCP 连接；首次安装 npm 依赖需要网络或已有缓存。

## 打开示例

安装 Node.js 24 和 npm，下载并解压源码，在包含 `package.json` 的目录打开终端，运行：

```bash
node --version
npm --version
npm ci
npm run demo
```

Node 应显示 `v24.x`，npm 会显示版本号。依赖安装结束后，示例会构建并启动服务。打开终端输出的一次性本机链接，保持终端运行。每次重新运行示例，都会生成新的临时文件和会话入口。

如果拿到的是**预构建 ZIP**，改用 `npm ci --omit=dev` 安装运行依赖，再运行 `npm run demo`。它已经构建好，不要在这个包里执行源码构建命令。

## 完成一次操作

页面右上角的“语言”菜单可选择简体中文或英文，浏览器会记住选择。

| 步骤 | 操作                                                                       | 应看到的结果                                    |
| ---- | -------------------------------------------------------------------------- | ----------------------------------------------- |
| 1    | 在“来源客户端”中保留 Codex CLI 和“包含全局配置”，点击“扫描原生配置”        | 出现 review-checklist Skill 与 example_docs MCP |
| 2    | 只勾选 review-checklist，展开“审查所选内容”，再点击“保存所选资源”          | Skill 标为“已保存”；此时还没有写入目标          |
| 3    | 在独立的“目标客户端”中保留 Claude Code                                     | 来源和目标分别选择，无需取消来源 Codex          |
| 4    | 点击“预览变更”                                                             | 1 项文件变更、0 项冲突及跨客户端审查提示        |
| 5    | 阅读目标路径、“变更前”“变更后”与提示，点击“应用已审查变更”，再点“确认执行” | 配置已应用，出现本地检查清单；原生加载待确认    |
| 6    | 点击“回退配置”，再点“确认执行”                                             | 配置已回退                                      |

不要为这次体验选择 example_docs：它是不可连接的 MCP 示例。Skill 正文会原样保留，跨 agent 提示提醒你真实使用前检查各客户端的 frontmatter、工具及权限语义。

应用后自动填入的“操作 ID”用于指定要回退的那次写入。退出时在终端按 **Ctrl+C**；临时示例文件仍保留在终端打印的目录，方便检查。

## 先选择任务

页面默认选择“复制给另一个客户端”。选择“迁移到新机器”后，扫描、选择并保存资源，填写本机 ZIP 绝对路径，导出后自行传输文件。到了目标机器，选择“使用配置 ZIP”，输入目标机器上的 ZIP 路径，读取、选择并保存资源，预览目标文件后再应用。项目资源需要用相同的逻辑项目 ID 映射目标目录。“回退配置变更”用于查看记录并恢复指定操作。

## 应用后逐项检查

应用后会自动显示“迁移后：哪些已经就绪？”的本地检查。分别查看目标配置、已声明依赖版本、可执行程序、环境变量引用、原生授权、独立 MCP 探测和原生加载。“与保存资源一致”确认的是目标文件；“原生加载：待确认”仍需你在原生客户端确认。

修复依赖或配置后，点击“刷新本地检查”。检查仅读取文件及 Shellter 进程环境，原生客户端可能使用不同环境，不会启动程序或连接服务器。MCP 的“审查连接探测”会单独要求确认，因为它可能启动程序或连接服务器；探测成功仍不代表原生加载成功。示例 MCP 不可连接，体验时保持不选。

## 几个词分别是什么意思？

- **扫描**：读取所选原生配置，不改写。
- **保存所选资源**：保存你选定的资源，还没有写入目标客户端。
- **计划**：展示将要修改什么，以及冲突和提示。
- **应用**：写入已确认的配置，并记录本机备份 journal。
- **回退**：在没有后续冲突修改的情况下，恢复这次写入之前的配置。

## 使用自己的配置

先停止示例。在源码目录运行：

```bash
npm run build
npm start
```

预构建包安装完运行依赖后直接运行 `npm start`。这次会使用你的实际 HOME，但仅启动不会扫描或改写。

1. 只选择想读取的来源 agent 和范围。项目映射填写已经存在的目录，例如 `work=/absolute/project`，一行一个。
2. 扫描并审查内容，只勾选需要管理的资源，再点击“保存所选资源”。
3. 在独立的“目标客户端”区域选择目标。项目迁移时保留相同的逻辑 ID，并填写目标目录。
4. 生成计划，解决冲突与必需路径映射，阅读提示及前后内容。
5. 确认目标文件无误后再应用，保存返回的操作 ID。
6. 去原生客户端确认实际加载和认证；文件写入成功不代表这两项成功。

备份 journal 可能含原始凭据，应保留在私有本机目录。ZIP 迁移与启动参数路径分类见 [CLI 指南](CLI.md)，已验证范围见 [兼容说明](COMPATIBILITY.md)。

## 常见问题

| 问题                 | 处理方法                                                    |
| -------------------- | ----------------------------------------------------------- |
| 找不到 node 或 npm   | 安装 Node 24，重新打开终端，再检查两个版本                  |
| 找不到 package.json  | 进入解压后的项目目录，不要停在它的父目录或 ZIP 文件上       |
| npm 安装失败         | 看第一条 npm 错误，检查网络、代理和目录/缓存权限            |
| 会话入口无效或已使用 | 保持服务运行；重启后使用最新启动链接                        |
| 扫描没有资源         | 示例中选择 Codex 和全局范围；真实环境所选范围也可能确实为空 |
| 出现冲突或缺少映射   | 阅读计划，选择受支持的来源/目标，并补齐明确路径             |
| 未能确认加载         | 到原生客户端确认，配置写入本身不能证明加载                  |
| 回退遇到漂移         | 先检查后来改动，不要强行覆盖                                |

更多截图见 [详细演示](DEMO.md)。`npm run demo:walkthrough` 可自动验证配置迁移和回退。

## 使用 tclaude 等独立配置目录

先确认实际客户端使用的目录。这次本机 `tclaude auth status` 返回 `~/.tclaude`，因此启动方式是：

```bash
node dist/cli.js --claude-config-dir "$HOME/.tclaude" serve
```

来源选 **Codex CLI**，目标选 **Claude Code**。扫描和应用前核对页面的 **全局配置位置**：来源 Skills 为 `~/.agents/skills`，目标 Skills 为 `~/.tclaude/skills`，目标 MCP 为 `~/.tclaude/.claude.json`。也可用环境变量 `CLAUDE_CONFIG_DIR`，显式参数优先；只影响 Claude 全局配置。后续 CLI 规划和检查继续使用同一参数。不要把 `--home` 改成 `.tclaude`，否则 Codex 的扫描位置也会被改变。

资源多时用 **查找资源** 按名称、类型、客户端或项目搜索。**选择筛选结果** 会追加匹配项，筛选保留其他已有选择；**清空选择** 会清空全部选择。保存前核对总选择数并审查所有所选内容。未搜索时可用 **选择全部可用资源**。被排除的资源不会选中，每项会显示名称、位置和原因。预览中逐项展开文件；重复的跨客户端警告会合并展示。迁移后的检查先显示文件一致数量，异常项保持展开。

重启 tclaude，确认 Skills 可见，再尝试一个小请求。文件一致、客户端发现、实际执行成功是三个不同结果；即使登录状态正常，真实请求失败也不能算调用成功。MCP 另在 `/mcp` 中检查，应用内专用服务、令牌和 OAuth 会话不能直接视为可迁移内容。详见 [真实迁移案例](REAL-MIGRATION.md)。

MCP 探测显示 **待授权**（HTTP 401）时检查原生登录或本机凭据绑定；**权限不足**（HTTP 403）时核对地址、账号权限和令牌 scopes，重复登录未必能解决。网络或服务错误单独报告为失败。


### 看懂内容，安全回退

展开“审查所选内容”，可按文件阅读保留换行的原文；MCP 声明仍以结构化 JSON 展示。预览出现冲突时，先看拟议差异，再决定是否允许覆盖并重新预览。

应用后点击“检查回退条件”，查看每个目标文件是否有阻止回退的后续编辑。先把这些编辑单独保存，再在本机检查私有备份记录或手动合并。备份可能含原有凭据，请勿分享。执行回退时仍会重新检查文件。

`npm run demo` 中，文件检查匹配并成功回退配置即完成示例；真实迁移才需要另行验证原生客户端加载。符号链接路径被拒绝时，请核对错误提供的真实路径候选，再显式使用该路径，不要关闭安全检查。
